# Contributing

Contributions are welcome when they make Diffcipline more correct, more portable, easier to verify, or simpler without weakening safety.

## Before opening a PR

- Keep the change focused.
- Explain why the change needs to exist.
- Reuse existing code before adding abstractions or dependencies.
- Add or update verification for changed behavior.
- Run formatting, linting, and tests for the touched surface.
- Include benchmark evidence for claims about agent quality, cost, speed, or code reduction.

Claims without reproducible evidence should be phrased as hypotheses, not results.
